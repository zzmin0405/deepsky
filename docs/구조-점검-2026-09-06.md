# 구조 점검 및 개선

## 현재 구조

- `src/routes`: SvelteKit 페이지와 서버 API. 홈은 날씨 조회, `chatbot`은 자연어 질문, `tip`과 `location`은 안내 콘텐츠, `community`는 게시판이다.
- `src/lib/server/weatherContext.js`: 질문의 지역·시간 해석과 예보 기반 관측 판단 및 장소 추천을 담당한다.
- `src/lib/server/observingPlaces.js`: MySQL 관측 장소와 로컬 대체 데이터를 제공한다.
- `src/lib/server/db.js`, `prisma`: MySQL 연결과 게시글·예보 캐시·관측 장소 모델을 관리한다.
- `src/lib/api`: 날씨 및 천문 관련 외부 데이터 조회를 담당한다.

현재 규모에서는 SvelteKit 구조를 유지하는 것이 적절하다. 이번 변경은 날씨 API 하드코딩, 환경 변수, DB 스키마 및 기존 미커밋 작업을 변경 대상으로 삼지 않았다.

## 반영 사항

1. 게시판 목록·최근 글·상세·수정 화면과 JSON API의 공개 조회에서 `passwordHash`를 제외했다. 수정·삭제 인증을 위한 서버 내부 조회는 유지했다.
2. 챗봇 마크다운은 DOMPurify를 거쳐 허용한 문서 태그와 링크 속성만 렌더링한다. 원시 HTML의 이벤트 속성 및 위험한 링크를 그대로 삽입하지 않는다.
3. 위치 조회 전에 전송 상태를 잠가 연속 클릭을 방지했다. 한글 입력 조합 중 Enter 전송을 막고 DOM 갱신 이후 스크롤하도록 수정했다.
4. 챗봇 API에서 잘못된 JSON, 빈 질문, 문자열이 아닌 질문, 2,000자 초과 질문을 거부한다.
5. LLM 요청에 15초 제한을 적용했다. 네트워크 실패·비정상 응답에서도 확보한 예보 요약을 반환하며, 예보가 없으면 현재 날씨를 단정하지 않는 기본 안내를 반환한다. 외부 API의 오류 상세는 클라이언트에 노출하지 않는다.
6. 존재하지 않는 `/contact` 메뉴를 제거하고 챗봇 마크다운 스타일의 잘못된 클래스명을 수정했다.

## 검증

- `npm run check`: 오류 및 경고 없음.
- `npm run build`: 성공.
- `node tests/security-regression.mjs`: 공개 조회 5곳의 해시 제외, 잘못된 요청 5종, LLM 네트워크 실패 시 대체 응답 검증. DB 조회는 대역으로 검증하며 실제 게시글을 생성·수정·삭제하지 않는다.
- 브라우저에서는 `/chatbot` 추천 질문의 전송 상태 및 응답을 확인한다.

## 이번 점검의 범위 밖

장소 안내 페이지의 정적 목록은 추천 서버의 장소 데이터와 별개여서 장기적으로 통합할 여지가 있다. 의존성 설치 시 npm audit은 취약점 19건을 보고했다. 프레임워크 및 의존성 전체 업데이트와 운영 DB 연결 검증은 이번 수정의 검증 범위에 포함하지 않는다.

HTML 정제 설정은 [DOMPurify 공식 문서](https://github.com/cure53/DOMPurify)를 참고했다.
